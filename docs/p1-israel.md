# יציאת P1 במוני חברת החשמל (קאיפה)

מה ידוע על יציאת ה-P1 במונים החכמים של חברת החשמל. בכל סעיף כתוב מאיפה המידע: **אומת** פירושו שנבדק על מונה אמיתי בפרויקט הזה. מידע ציבורי כמעט אין, מעבר לשני הפרויקטים שבסוף המסמך.

---

## בקצרה

| | |
|---|---|
| תקן | DSMR 5.0 (‏`1-3:0.2.8(50)`), מונה הולנדי של קאיפה שהותאם לישראל |
| כותרת | `/KFM5KAIFA-METER` |
| תקשורת | ‏115200 באוד, 8N1, **לוגיקה הפוכה** |
| קצב | מברק כל שנייה בדיוק (**אומת**: 404 מברקים רצופים, אף שנייה לא חסרה) |
| CRC | CRC16, פולינום 0xA001 (reflected), ערך התחלתי 0, מה-`/` עד ה-`!` כולל, כולל `\r\n` בסוף כל שורה (**אומת**) |
| אורך מברק | כ-500 בתים בחד-פאזי |
| מתח מהמונה | ‎+5V, **עד 250mA** לפי DSMR. ראו [hardware.md](hardware.md#תקציב-זרם) |

## החיבור הפיזי (RJ12 6P6C)

| פין | אות | הערה |
|---|---|---|
| 1 | ‎+5V | מבודד מהרשת |
| 2 | Request | כשיש עליו ‎+5V המונה משדר. מחברים דרך 1kΩ לפין 1. **לא** ל-GPIO |
| 3 | Data GND | |
| 4 | — | לא מחובר |
| 5 | Data | open collector מאופטוקופלר. pull-up של 1kΩ ל-3.3V. **הפוך** |
| 6 | Power GND | |

- **כבל:** חייב להיות 6P6C, כלומר 6 גידים. רוב כבלי הטלפון הם 6P4C או 6P2C, וחלקם נמכרים בשם "RJ12" בטעות.
- **כבל שטוח מתהפך:** פין 1 בצד אחד הוא פין 6 בצד השני. לכן מודדים ‎+5V בין פין 1 לפין 6 **לפני** שמחברים ESP.
- **ההיפוך** נעשה בתוכנה (`Serial.begin(..., invert=true)`), בלי טרנזיסטור.

## הקודים

| קוד | משמעות | הערות |
|---|---|---|
| `1-3:0.2.8` | גרסת DSMR | `50` |
| `0-0:1.0.0` | שעון המונה | `YYMMDDhhmmss` ואחריו `W` (חורף) או `S` (קיץ). שעון מקומי |
| `0-0:96.1.1` | מזהה מונה | **טקסט רגיל** (`Kxxxxx`). בהולנד הוא בקידוד hex. הקושחה מטפלת בשניהם. **לא ייחודי:** שני המונים במשק שולחים אותו מזהה (`Kxxxxx`) |

### בדיקת עקביות (**אומת**)

ב-403 שניות של ההקלטה, `1.8.13` עלה ב-0.112 קוט"ש. זה ממוצע של 1.00kW, והמדידה הרגעית נעה בין 0.89 ל-1.20kW.

## פרופיל העומס `1-0:99.1.0` (**אומת**)

```
1-0:99.1.0(1)(0-0:96.10.7)(1-0:1.29.0)(1-0:2.29.0)(261104014500W)(00)(000000.212*kWh)(000000.000*kWh)
           │   │            │           │           │              │   │                │
           │   │            └───────────┴ קודים    │              │   └ צריכה          └ ייצוא
           │   └ קוד הסטטוס                         │              └ סטטוס
           └ מספר רשומות                            └ זמן **סוף** התקופה
```

- **רשומה אחת:** המונה שולח רק את הרבע שעה האחרון שהסתיים.
- **הזמן הוא סוף התקופה.** ב-02:00:00 הרשומה התחלפה מ-`014500` (0.212kWh) ל-`020000` (0.220kWh). ‏0.220kWh ב-15 דקות הם 0.88kW בממוצע, וזה תואם למדידה החיה.
- **זו האנרגיה הרשמית** שהמונה מחשב לרבע שעה, כנראה זו שמשמשת לחיוב לפי שעה. היא מדויקת יותר מסכום של מדידות רגעיות.
- **בקושחה:** השדות `lp_end` (זמן), `lp_in` ו-`lp_out` (קוט"ש). ב-HA הם מסוג `energy`, בלי `state_class`, כי הם לא מצטברים.
- **הפענוח כללי:** סופרים את הקבוצות שיש בהן `:` (קודים), ומהן יוצא רוחב כל רשומה. כך גם מונה ששולח יותר ערכים, או יותר רשומות, ייקרא נכון.

## תעריפים

- **`96.14.1 = 1` הוא פסגה, ו-`3` הוא שפל (אומת).** במשק, ב-2026-11-05, התעריף עבר מ-3 ל-1 בדיוק ב-17:00:00 (פסגת חורף של תעו"ז 17:00-23:00). אחרי המעבר הייצוא נרשם ב-`2.8.11` (‏74.216 → 74.26kWh), ולפני כן ב-`2.8.13`. בצהריים ובלילה התעריף 3.
- **הרגיסטרים:** `x.8.11` = פסגה (T1), `x.8.13` = שפל (T3). `x.8.12` (גבע) תמיד 0. גם בבית רוב הצריכה ב-`1.8.13`.
- **המונה מחליף תעריף גם אצל לקוח בתעריף אחיד.** החלוקה לפסגה ושפל קיימת תמיד, והמחיר נקבע לפי המסלול של הלקוח. בממשק התעריף הפעיל מוצג בשמו (פסגה / שפל), והמחיר לפי ההגדרות.
- **הקושחה מתמחרת כל רגיסטר בנפרד** (מצב `tou`).

## ייצוא בבית בלי סולארי

ב-`2.8.13` רשומים 0.036kWh לאורך כל חיי המונה, למרות שאין בבית מערכת סולארית. כנראה מדובר ברעש או בהתקנה. לכן הזיהוי של "סולארי" דורש ייצוא מצטבר של 1kWh לפחות, או הספק ייצוא רגעי של 0.1kW לפחות.

## מה עדיין חסר

1. **מעבר תעריף בבוקר** (23:00 → שפל, ובקיץ גם שעות אחרות), כדי לאשר את לוח הזמנים המלא.
2. **מברק אחרי הפסקת חשמל**, כדי לראות אם `96.7.21` (מונה הפסקות) קיים.

איך מקליטים: בממשק, לשונית **מונה** ← "הקלטת מברקים". הקובץ נשמר ב-`/raw/` בכרטיס.

## לא רלוונטי

- **MA309M באוסטריה** משדר M-Bus מוצפן. זה פרוטוקול אחר, ולכן מדריכים אוסטריים לא מתאימים.
- **רכיב `dsmr` של ESPHome** (גרסה 2025.11) לא מכיר את הקודים `1.8.11`–`1.8.13`.
