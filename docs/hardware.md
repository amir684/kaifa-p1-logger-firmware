# חומרה וחיווט — P1 Logger

אב-טיפוס על לוח ESP32-S3-DevKitC-1 N16R8. כל מספרי הפינים מוגדרים.

**לוח N16R2** (‏2MB PSRAM מסוג Quad) עובד עם אותם פינים ואותו חיווט, אבל צריך קושחה משלו: `-r2`. קושחה של N16R8 לא תזהה בו את ה-PSRAM. ב-N16R2 המאגרים קטנים יותר, ולכן כשהכרטיס לא זמין יש כ-2 שעות לנתוני שנייה (במקום 12) וכ-15 שעות לנתוני דקה (במקום 2.5 ימים). בשימוש רגיל אין הבדל.

**ESP32-S3 Super Mini** (‏N4R2: פלאש 4MB, ‏2MB PSRAM): קושחה משלו, `-mini`, עם מיפוי פינים אחר. ראו [Super Mini](#esp32-s3-super-mini) בהמשך.

## ESP32-S3 Super Mini

כל החיבורים על הפינים בשולי הלוח הקדמיים (1–13, 43, 44), בלי המשטחים שמתחת ללוח. ההגדרות תחת `BOARD_SUPERMINI`.

| GPIO | חיבור | | GPIO | חיבור |
|---|---|---|---|---|
| 9 | P1 Data (RJ12 פין 5) + 1kΩ ל-3V3 | | 5 | LCD SCK |
| 12 | SD SCK | | 6 | LCD MOSI |
| 13 | SD MOSI | | 7 | LCD CS |
| 11 | SD MISO | | 1 | LCD A0 (DC) |
| 10 | SD CS | | 2 | LCD RST |
| 44 | Gate של ה-P-MOSFET לניתוק מתח הכרטיס | | 3 | LCD תאורה |
| 4 | VBUS sense | | 0 | BOOT (על הלוח) |
| 8 | VBAT sense | | 48 | LED RGB (על הלוח) |
| 43 | פנוי (‏U0TXD: ה-ROM מדפיס עליו בעלייה) | | | |

**ההבדלים מהלוח הרגיל:**
- **הכרטיס עובד ב-SPI** (ברירת המחדל), או ב-SDMMC 1-bit. שני המצבים משתמשים באותם 4 חוטים. אין SDMMC 4-bit.
- **ניתוק מתח הכרטיס על פין 44 מוגדר מראש.** נגד pull-up על ה-Gate משאיר את הכרטיס כבוי עד שהקושחה מדליקה אותו. אם אין MOSFET, הפין פשוט לא מחובר, ולא צריך לשנות שום הגדרה.
- **אין לחצני תפריט.** משתמשים רק ב-BOOT שעל הלוח: לחיצה קצרה עוברת לדף הבא, ולחיצה של 1–3 שניות פותחת את התפריט. בתוך התפריט, לחיצה קצרה עוברת לפריט הבא, ולחיצה ארוכה בוחרת.
- **אין RTC.** המונה שולח את השעה בכל שנייה.
- **פלאש 4MB:**
  - שני סלוטים של 1.56MB לעדכון OTA. הקושחה כרגע תופסת כ-82% מסלוט.
  - 768KB לזיכרון הפנימי. זה מספיק לכ-5 ימים של דקות במונה חד-פאזי, ולכ-2–3 ימים בתלת-פאזי.
- **הצריבה הראשונה רק ב-USB**, כי טבלת המחיצות שונה: `-mini`. אחר כך העדכונים עוברים ב-OTA.
- **הרגולטור של 3.3V בלוח קטן,** בדרך כלל עד 500mA. ‏WiFi וכרטיס SD ביחד מגיעים לכ-450mA בשיא.

## יציאת P1 (RJ12)

| פין RJ12 | אות | חיבור |
|---|---|---|
| 1 | ‎+5V | → polyfuse → הגנת קוטביות → כניסת IN של BQ24074. גם דרך 1kΩ לפין 2 |
| 2 | Request | 1kΩ לפין 1 בלבד. **לא** ל-ESP |
| 3 | Data GND | GND |
| 4 | — | לא מחובר |
| 5 | Data (open collector) | **GPIO39**, ו-1kΩ מ-GPIO39 ל-3V3 |
| 6 | Power GND | GND |

TVS בין ‎+5V ל-GND, צמוד לשקע.

**לפני החיבור הראשון:** מודדים בין פין 1 לפין 6 עם הכבל במונה וה-ESP מנותק. צריך להיות **‎+5V**.

## חשמל (UPS)

```
P1 +5V ─ polyfuse ─ P-MOSFET ─┬─ BQ24074 IN        BQ24074 OUT ─┬─ buck-boost ─ 3V3 ─ ESP32-S3 (3V3 pin)
                              │   ILIM → ~200mA                  ├─ 470µF
                              │   BAT ── 18650                   │
                              └─ 100k/100k → GPIO4 (VBUS sense)  └─ (OUT = קו המערכת)
   BAT ─ 100k/100k → GPIO8 (VBAT sense)
   BQ24074 TS ─ תרמיסטור 10k NTC צמוד לסוללה (חוסם טעינה בחום/קור)
```

- **ILIM:** קובעים את הנגד ב-ILIM של BQ24074 להגבלת זרם כניסה של כ-200mA (לפי הדאטהשיט). ככה לעולם לא חורגים מ-250mA של יציאת P1; הסוללה משלימה שיאים.
- **המתח ל-ESP** נכנס ל**פין 3V3** של הלוח (לא ל-5V), כי הממיר כבר מספק 3.3V.
- **מחלקי מתח:** 100k/100k נותנים יחס 2.0 (ברירת המחדל בהגדרות). אם אין מחלק, הקושחה מזהה זאת ומכבה את המדידה. אפשר גם לכבות ידנית (יחס 0).
- **בהפסקת חשמל:** הקושחה מזהה ירידה של VBUS, כותבת את כל הנתונים לכרטיס ורושמת אירוע. כשהסוללה יורדת מתחת ל-3.3V (מוגדר) היא סוגרת את הכרטיס ונכנסת לשינה עמוקה; חזרת ה-5V מעירה אותה.
- **בלי UPS (שלב ראשון):** אפשר לחבר את ‎+5V מהמונה ישר ל-5V של הלוח, עם קבל 470µF. הכול עובד, רק שבהפסקת חשמל המכשיר כבה מיד.

## תקציב זרם

ה-5V של יציאת P1 מוגבל ל-**250mA** לפי DSMR, ובמונים של חברת החשמל אולי אף פחות. זה לא מספיק לשיאים של המערכת:

| צרכן | זרם ב-3.3V | הערה |
|---|---|---|
| ESP32-S3, ‏WiFi משדר | ‏350–500mA | פולסים קצרים, ב-19.5dBm |
| ESP32-S3, ‏WiFi בהמתנה | ‏80–120mA | `WiFi.setSleep(false)` |
| microSD בכתיבה | ‏50–100mA | פולסים |
| צג + תאורה | ‏5–20mA | |

**חישוב:** ‏500mA ב-3.3V הם כ-1.65W. אחרי buck ביעילות של כ-90%, זה כ-**370mA ב-5V**, יותר ממה שהמונה נותן. בממוצע המערכת צורכת הרבה פחות, ולכן הבעיה מופיעה רק כששיא של WiFi נופל על כתיבה לכרטיס.

**מה קרה באב-טיפוס** (2026-11-04): הכול הוזן מה-5V של המונה דרך buck ל-3.3V. אחרי 8 דקות של כתיבה תקינה, הכרטיס נתקע באמצע כתיבה. ה-ESP המשיך לרוץ. רק ניתוק מתח החזיר את הכרטיס.

**מה עושים, לפי הסדר:**
1. **הגבלת זרם בכניסה + סוללה:** זה ה-UPS שלמעלה. ה-BQ24074 מגביל את הזרם **מהמונה** ל-200mA, והסוללה מספקת את השיאים. זה הפתרון הנכון. מטען TP4056 לא מתאים: הוא מגביל רק את זרם הטעינה, והעומס ממשיך למשוך מהכניסה בלי הגבלה.
2. **קבלים:** ‏470–1000µF ביציאת ה-buck, ‏100–220µF בכניסה שלו, ו-100µF + 100nF צמוד למודול הכרטיס.
3. **עוצמת WiFi נמוכה:** `wifi.tx_power`. ב-11dBm השיאים קטנים בכ-100mA. מתאים כשהנתב קרוב, למשל ב-RSSI של -49dBm כמו בבית.
4. **ספק חיצוני** (מטען USB): פותר הכול, אבל מוסיף כבל.

**מדידה:** מודדים את ה-5V בפין 1 של ה-RJ12 בזמן עבודה, וגם בזמן שהממשק פתוח בדפדפן. אם הוא יורד מתחת ל-4.7V, המונה לא עומד בעומס.

## microSD

| כרטיס (SD) | SDMMC | SPI |
|---|---|---|
| CLK | GPIO12 | SCK |
| CMD | GPIO13 | MOSI |
| D0 | GPIO11 | MISO |
| D1 | GPIO10 | — |
| D2 | GPIO9 | — |
| D3 | GPIO14 | CS |

- pull-up של 10kΩ ל-3V3 על CMD, D0–D3 (בחלק מהמודולים כבר קיים).
- מצב העבודה נבחר בממשק: SDMMC 4-bit (מומלץ), 1-bit, או SPI למודולים שבנויים ל-SPI.
- מודול עם ממיר רמות ל-5V **לא** מתאים ל-SDMMC.
- **מתח יציב לכרטיס:**
  - כרטיס SD מושך שיאים של כ-100mA בזמן כתיבה. צניחת מתח באותו רגע יכולה "לתקוע" אותו, עד שמנתקים לו את המתח.
  - מומלץ קבל 100µF + 100nF צמוד לפיני VCC/GND של המודול, וחוטים קצרים.
  - כרטיס תקוע משחררים כך: מוציאים אותו ומכניסים שוב, **בלי** לאתחל את הבקר. הנתונים שהצטברו בזיכרון נשמרים ונכתבים.
- **ניתוק מתח אוטומטי לכרטיס (מומלץ):** טרנזיסטור P-MOSFET בקו ה-3V3 של הכרטיס מאפשר לקושחה לנתק לו את המתח בעצמה, במקום שמישהו יוציא ויכניס אותו.
  - **רכיבים:** P-MOSFET ל-logic level, למשל AO3401 או Si2301, ונגד 10kΩ.
  - **חיבור:** Source ל-3V3. Drain ל-VCC של מודול הכרטיס. Gate ל-GPIO פנוי, למשל GPIO1, ונגד 10kΩ מה-Gate ל-3V3, כדי שהכרטיס כבוי עד שהקושחה עולה.
  - **בממשק:** בלשונית **כרטיס**, בשדה "פין לניתוק מתח הכרטיס", רושמים את מספר ה-GPIO.
  - **מה הקושחה עושה:** אחרי כתיבה שנכשלה או חיבור שנכשל, היא מנתקת את המתח לחצי שנייה לפני הניסיון הבא. בזמן הניתוק היא מחזיקה את קווי הנתונים ב-LOW, כדי שהכרטיס לא יקבל מתח דרכם. מספר הניתוקים מופיע בלשונית **כרטיס**.

**תחזוקה מהממשק** (לשונית **כרטיס**):
- **פרמוט:** FAT32 עם אשכול של 32KB, דרך SPI, בכל מצב עבודה. מתאים לכרטיס חדש, לכרטיס גדול מ-32GB שמגיע ב-exFAT, ולכרטיס שפורמט במצלמה או בטלפון. מוחק את כל הקבצים. נתונים שעוד בזיכרון נכתבים לכרטיס אחר כך.
- **בדיקת כרטיס:** כותבת 1MB, קוראת אותו חזרה ומשווה. מציגה מהירות כתיבה וקריאה ואת הכתיבה האיטית ביותר. כתיבה של יותר מחצי שנייה מעידה על כרטיס איטי, שנתקע בקלות רבה יותר.
- **פרטי הכרטיס:** סוג, מערכת קבצים, גודל אשכול, תפוסה לפי תיקייה, גידול ליום, ובעוד כמה שנים הכרטיס יתמלא.
- הפינים 11–14 הם גם פיני ברירת המחדל של FSPI ב-S3. הקושחה דואגת שהצג (על FSPI) לא יתפוס אותם; ראו `displayBegin()`.

## צג ST7567

| צג | ESP32-S3 |
|---|---|
| SCK / SCL | GPIO5 |
| SDA / MOSI | GPIO6 |
| CS | GPIO7 |
| A0 / RS / DC | GPIO15 |
| RST | GPIO16 |
| LED / BL | GPIO18 (ראה תאורה למטה) |
| VCC | 3V3 |

**תאורה:** ברירת המחדל מתאימה לצג "הישן" מפרויקט השעון STM32F401: אנודת ה-LED ל-3V3, קתודה ישר ל-GPIO18 בלי נגד, דולק ב-LOW, ו-PWM מוגבל ל-25% (`LCD_BL_MAX_PWM 64`). "תאורה %" בממשק הוא אחוז מהתקרה הזו. אם מחברים דרך טרנזיסטור (דולק ב-HIGH), מוסיפים ב-`platformio.ini`: ‏`-DLCD_BL_ACTIVE_LOW=0 -DLCD_BL_MAX_PWM=255`. לא להעלות את התקרה בלי נגד.

יש כמה גרסאות של מודולי ST7567 (JLX12864, OS12864, DG128064). בוחרים בלשונית **צג**; אם התמונה הפוכה, מסומנים "סיבוב 180°"; אם חיוורת או שחורה, משנים ניגודיות.

### צג 96×48

**החיווט** זהה לצג 128×64: אותם פינים, אותו בקר ST7567. בלשונית **צג** בוחרים "ST7567 96×48" ומאתחלים.

**הדפים:** אותם 8 דפים כמו בצג הגדול, עם תוויות קצרות וגופן קטן לערכים. במסך הראשי, ייצוא לרשת מסומן במינוס לפני המספר.

**מיקום הזכוכית:**
- **למה צריך לכוון:** לבקר יש זיכרון של 132×64, וזכוכית של 96×48 מחוברת רק לחלק ממנו. איזה חלק בדיוק משתנה בין יצרנים. U8g2 לא מכירה את הגודל הזה, ולכן הקושחה משתמשת בדרייבר של JLX12864 עם מאגר 96×48.
- **איך מכוונים:** משנים את "הזזה אופקית" (`display.offset_x`, ‏0–36) ואת "הזזה אנכית" (`display.offset_y`, ‏0–63). אחרי כל שמירה, הצג מראה למשך 20 שניות מסגרת כפולה ואת הערכים הנוכחיים.
- **מה מחפשים:** הקו החיצוני צריך לגעת בכל ארבע הקצוות של הזכוכית.
  - קו חסר משמאל או מימין: משנים X. ערכים נפוצים הם 0, 4, 32 ו-36.
  - קו חסר למעלה או למטה: משנים Y. ערכים נפוצים הם 0 ו-16.
